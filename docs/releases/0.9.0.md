# Scratch Tab 0.9.0

This release includes all unreleased work following v0.8.0. Earlier local ZIPs used v0.8.1; the complete feature set is versioned v0.9.0.

## Files and editing

- Folder expansion/collapse preserves the sidebar viewport through delayed listings and errors, including keyboard toggles and the phone drawer.
- Picking a new or already-open file preserves the sidebar viewport. Selecting an editor tab still reveals its file and expands its parent folders.
- A line-number gutter updates while editing plain text and highlighted code. Blank/trailing lines, wrapped lines, scrolling and mobile sizing stay aligned.
- Directory listings use Scratch Tab's project backend, without relying on the removed chat-listing endpoint or a File Manager installation. Rooted filesystem access enforces the workspace boundary; symlinks and irregular files are omitted and listings are capped at 10,000 entries.
- The shared filterable picker supports keyboard navigation, staged indentation actions/tab-size choices, selected items and focus return. Git repository selection uses the same control.
- Files, Source Control and graph panels have draggable, keyboard-adjustable sizes remembered in browser storage. Bounds protect the editor area; double-click or Enter resets defaults. Phone drawers retain their layout.

## Git Source Control

- Compact Files and Source Control activity buttons switch views.
- Active-repository lookup loads useful status/graph data before bounded background discovery of nested repositories and worktrees. Slow repositories load independently; reopening reuses discovery and Refresh rescans.
- Each repository has its own commit message, branch/upstream status, staged and working-tree groups, counts and primary actions. Context menus close one/other repositories and closed repositories can be reopened.
- Stage/unstage individual files or entire groups, including rename partners. Commit staged changes or explicitly commit all saved changes.
- Fetch, fast-forward-only pull, push, sync and branch publication use existing container remotes and credentials. Confirmation prompts protect pull/push-related operations. Git errors appear in the panel.
- The history graph shows lanes, merge connections, refs and commit metadata, with a filterable repository selector and independent loading.
- Diffs include unified and split views, syntax and word highlighting, line numbers, wrapping, change counts, file status and missing-final-newline indicators. Narrow windows use unified view; view/wrap preferences persist.
- Diff warming and bounded caching reduce repeat requests. Saves, refreshes and Git operations invalidate cached data; stale responses cannot replace a selected file or reopen a closed diff.
- Git subprocesses use fixed arguments and bounded output/time. Reads bypass the global save lock; mutations remain serialized. Git receives a longer host deadline while ordinary file commands retain their short deadline. The application request ceiling is 120 seconds.

## Supporting changes

Release packaging uses the `vX.Y.Z` tag as its version and updates the checkout manifest before building the ZIP. An older manifest no longer blocks a tagged release. Invalid/prerelease tags are rejected; the checkout change is not committed automatically.

Production TypeScript configuration excludes test/spec files; the dedicated test configuration continues checking tests. Regression coverage includes API validation, workspace boundaries, repository discovery, local remote operations, graph/diff presentation, viewports, sizing and mobile layouts.

## Upgrade

Install the complete ZIP through Remote's application management so the UI and container command upgrade together. Git must be installed in each project container. The application uses saved disk files; unsaved drafts must be saved before Git operations. Network credentials, identity, hooks and signing remain configured by the container.

No new external hosting, branch-management UI, destructive discard/reset operation, or automatic release publication is included.
